# Tama 产品规划（2026-11-25 版）

> 现状：v0.7.0，Windows 原生 Win32/C++17，单文件 1.3 MB，已移植作者的悬空姿态；仓库 https://github.com/123caiji/tama
> 问题：**目标不清晰**。本文先解决定位，再给 12 周可执行路线。

---

## 1. 现状盘点（有什么 / 缺什么）

### 已有能力

| 能力 | 状态 |
|---|---|
| 全局键盘可视化（键帽气泡 / 组合键合并 / 鼠标三键分色） | ✅ |
| 9 款数据驱动皮肤（`.kurocat` JSON）+ 换装间 + 拖入安装 | ✅ |
| DSH 状态联动（读 `state.json`） | ✅ |
| 后颈拖拽（含作者移植的悬空姿态） | ✅ |
| 安全更新检查（只查不装、固定 URL、6h 节流） | ✅ |
| 右键菜单分组 + 皮肤/瞳色/键盘配色切换 | ✅ |

### 缺失（工程底座）

| 缺项 | 影响 | 优先级 |
|---|---|---|
| **没有 CI**（GitHub Actions 只建不测） | 每次改动靠手工编译验证 | P0 |
| **没有单元测试**（仅 `skincheck` 手工跑） | 回归无保护 | P0 |
| **没有代码签名** | SmartScreen 警告、更新无法安全校验 | P0 |
| 无崩溃/错误上报（可选项，需隐私口径） | 线上问题靠猜 | P2 |
| 只有中文文档 | 海外用户看不懂 | P1 |
| 版本号语义混乱（v0.7.0 vs 上游 v1.4.3） | 用户困惑 | P1 |
| `build.cmd` 仅支持 MinGW | MSVC 用户编不了 | P2 |

## 3. 五个可选方向（挑一个当主线）

| 方向 | 一句话 | 目标用户 | 优势 | 风险 | 工作量 |
|---|---|---|---|---|---|
| **A. 键盘可视化工具**（对标 keyviz） | 把「你按了什么」做到最好，猫只是载体 | 做教程/直播/演示的人 | 需求明确、易传播、OBS 友好 | 与 keyviz 正面竞争，他们已 9.8k★ | 中 |
| **B. AI Agent 工作伴侣**（对标 dsh-pet） | 猫显示 Agent 在思考/干活/出错 | 用 DSH / Claude Code / Cursor 的开发者 | 生态空白、粘性高、我们已有状态联动 | 依赖 DSH 生态演进 | 中 |
| **C. 纯桌宠养成**（对标 BongoCat/VPet） | 好看、可爱、能互动 | 大众用户 | 传播快、皮肤市场大 | 视觉军备竞赛，BongoCat 已 24.8k★ | 大 |
| **D. 极简常驻工具** | 只占 30MB、开机就跑、零打扰 | 低配机/办公场景 | 我们原生 1.3MB 显著优势 | 用户感知弱、难变现 | 小 |
| **E. 皮肤创作平台** | 提供网页工坊 + 皮肤市场 | 二创作者 | 生态飞轮 | 需要云服务/审核，成本高 | 大 |

### 组合建议（推荐）

```text
主线：A（键盘可视化）× B（Agent 状态）——「工作时的猫」
支线：E 的静态版（皮肤画廊，不做市场）
不做：C（纯养成，正面硬碰 BongoCat）、D 单独成线（并入 A/B 作为卖点）
```

理由：A 有明确工具价值，B 有生态位；两者共用同一套「输入/状态 → 猫表现」的管线，实现成本可复用。

## 4. 需要先补的底座（P0，2 周）

| # | 任务 | 交付物 | 验收 |
|---|---|---|---|
| F-1 | GitHub Actions：Windows 构建 | `.github/workflows/build.yml` | push 即产出 artifact，编译失败会红 |
| F-2 | 自动化测试 | `skincheck` 接入 CI + 新增物理单测（弹簧收敛/边界值） | CI 里跑，全绿 |
| F-3 | 统一版本号 | 单一 `VERSION` 文件 → 脚本同步 APP_VERSION/rc/tag | 三处一致 |
| F-4 | 代码签名 | SignPath（开源免费）或自签方案评估 | exe 属性页显示签名、SmartScreen 无警告 |
| F-5 | 打包 | zip（便携）+ 可选 winget 清单 | 解压即用、winget 可搜到 |

## 5. 12 周路线（按主线 A×B）

### 第 1–2 周：底座（F-1 ~ F-5）

目标：**任何人都能一键编译、CI 全绿、有签名产物**。

### 第 3–5 周：键盘可视化做到「工具级」

| 功能 | 说明 | 验收 |
|---|---|---|
| 键帽气泡布局引擎 | 多行不重叠、更大按键组合（4+ 键） | 连按 10 键无遮挡 |
| 鼠标轨迹可视化 | 拖拽/滚轮/双击区分 | 录屏可读 |
| OBS 直播源（本地 HTTP + SSE） | 跨机可用，网页端复刻猫 | 双机延迟 < 200ms |
| 历史面板 | 最近 30 次操作时间线 | 可关闭、不落盘 |
| 键位热力图（可选） | 一周击键分布 | 渲染 < 100ms |

### 第 6–8 周：Agent 状态伴侣

| 功能 | 说明 | 验收 |
|---|---|---|
| 状态桥 v2 | 支持 DSH / Claude Code / 任意进程写 `state.json` | 缺字段回退不崩 |
| 任务进度角标 | 读待办/进度，猫头顶显示小进度点 | 延迟 < 150ms |
| 完成/出错反馈 | 撒花 / 垂耳 + 可选音效 | 可关闭 |
| DSH 插件壳 `dsh-tama` | 薄插件：拉起 exe + 写状态 | 装完即用 |

### 第 9–10 周：皮肤与视觉

| 功能 | 说明 | 验收 |
|---|---|---|
| 皮肤统一光影标准 | 9 款皮肤描边/阴影/高光统一 | 截图对比无跳变 |
| 网页皮肤工坊（只读预览） | 浏览器里渲染 `.kurocat` | 9 款皮肤 1:1 一致 |
| 主题包 | 皮肤+键盘配色+瞳色 一键切 | < 200ms |

### 第 11–12 周：发布与传播

| 任务 | 验收 |
|---|---|
| README 英文化 + 5 张真实截图/GIF | 海外可读 |
| v1.0.0 发布（语义化版本重置） | Release 含签名 exe + 校验 SHA256 |
| 提交 winget / awesome 列表 | 可被搜索到 |

## 6. 验收总表（每个阶段都要过）

| 指标 | 红线 |
|---|---|
| 输入→画面延迟 | P95 ≤ 33 ms |
| 空闲 CPU（单核基准） | ≤ 2%（相对基线不劣化） |
| 常驻内存 | ≤ 40 MB |
| 启动到可见 | ≤ 1.5 s |
| 崩溃 | 连续 2h 无崩溃 |

## 7. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 与 keyviz/BongoCat 正面竞争 | 无人使用 | 走 A×B 交叉位，不拼形象也不拼纯键盘 |
| 没有代码签名 | 用户不敢装 | P0 就解决（SignPath 开源免费通道） |
| 单人维护 + 上游频繁更新 | 追不动 | 只挑单点修复移植，不整体合并，保持自有渲染 |
| 需求发散（像这次设置窗口/双态姿态反复） | 返工 | 每个功能先出「1 张对比图 + 1 条验收线」再动手 |

## 8. 需要你拍板（只问关键的）

1. **主线选哪个**：A（键盘可视化）/ B（Agent 伴侣）/ A×B（推荐）？
2. **受众**：自己用 / 给身边朋友 / 开源冲星？这决定要不要做签名、英文文档、市场。
3. **是否愿意上云**：OBS 源、皮肤工坊都涉及本地服务或静态托管——能接受「本地 HTTP」和「GitHub Pages」吗？
4. **v1.0 时间点**：3 个月（稳）/ 6 周（快，功能砍半）？
