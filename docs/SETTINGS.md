# 设置窗口（Tama 原生 UI）

> 右键小猫 → **⚙️ 设置…**，或启动时加 `--settings`。全部用 Win32 原生控件，无 HTML/无 WebView。

## 1. 为什么做它

旧版把所有开关堆在一级菜单里（20+ 项），观感差、也难找。现在菜单只剩 5 个入口，细项全部进窗口：

```text
右键菜单
├─ ⚙️ 设置…         ← 新窗口（本文档）
├─ 🐱 猫咪皮肤 ▸
├─ 🎨 外观 ▸
├─ 🖥 窗口 ▸
├─ ⚙ 系统 ▸
├─ 🌐 语言 ▸
└─ 退出 Tama
```

## 2. 窗口里有什么（566×549，随 DPI 缩放）

| 分组 | 控件 | 行为 |
|---|---|---|
| **外观** | 猫咪皮肤（下拉：6 内置 + 已导入皮肤） | 选中即换，和菜单同一套命令 |
| | 瞳色（下拉 7 种） | 即换 |
| | 键盘配色（下拉 3 套） | 即换 |
| | 缩放（65/85/100/125/150%） | 即换并保存 |
| | 换装间…（按钮） | 打开导入窗口 |
| **行为与反馈** | 显示键帽气泡 / 键位图例 / 键盘跑马灯 / 全屏自动隐藏 / 窗口置顶 / 鼠标穿透（勾选） | 勾选即生效并写注册表 |
| **系统** | 开机自启（勾选） | 写入 Run 键 |
| | 语言（简体中文 / English） | 即换（窗口下次打开时按新语言重建） |
| | 打开皮肤文件夹 / 检查更新（按钮） | 复用菜单命令 |
| **底部** | `Tama v0.4.0 · 上游致谢 chanke17/KuroCat (MIT)` + 完成按钮 | — |

## 3. 实现要点

| 点 | 说明 |
|---|---|
| 复用命令 | 控件事件统一走 `applyAppCommand(app, CMD_*)`，与右键菜单**同一套逻辑**，不会出现两处行为不一致 |
| 独立窗口类 | `TamaSettingsWindowClass`，`settingsWnd` 保存在 AppState 里，重复打开只刷新不重建 |
| DPI | 用 96-dpi 设计单位 × 系统 DPI 缩放；窗口居中到工作区 |
| 零依赖 | 只要 user32/gdi32；没有 WebView、没有 HTML |
| 安全 | 只读/写本机注册表键（`HKCU\\Software\\Tama`），不发网络请求 |

## 4. 实测（本机）

子控件枚举（`tools/wchildren.exe`）确认 27 个控件全部创建且可见，中文文本正确：

```text
Button   [外观]                532x150
Static   [猫咪皮肤] [瞳色] [键盘配色] [缩放]
ComboBox x4（皮肤/瞳色/键盘/缩放）
Button   [换装间…]
Button   [行为与反馈] 532x128
Button   [显示键帽气泡] [显示键位图例] [键盘跑马灯]
Button   [全屏时自动隐藏] [窗口置顶] [鼠标穿透]
Button   [系统] 532x96 + [开机自启] + 语言下拉
Button   [打开皮肤文件夹] [检查更新] [完成]
Static   [Tama v0.4.0 · 上游致谢 chanke17/KuroCat (MIT)]
```

> 已知限制：本机自动化环境里 `PrintWindow` / 屏幕 BitBlt 抓不到原生子控件（抓到的是纯背景），所以仓库里暂缺设置窗口的截图；窗口本身在你的屏幕上可见可用。
