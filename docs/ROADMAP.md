# ROADMAP · 二次创作方向（文档，不含实现）

> 本文件只做**方向与优先级**，不写代码。目的是让「自己的猫」和上游 KuroCat 拉开差异，而不是重复造 Bongo Cat。

## 0. 定位建议

上游已经占了两个位置：**轻量原生桌宠**（chanke）与**富功能跨平台桌宠**（qianyi）。本工程若要有存在价值，建议占第三个位置：

> **「可读操作反馈 + 皮肤工坊」的自用工具** —— 不只是看的猫，而是能把「你刚才按了什么」讲清楚，并且皮肤是可以用网页画出来的。

差异化的三条护城河：**皮肤是数据（可编辑/可分享）**、**操作信息可读（键名/组合/鼠标）**、**完全离线零依赖**。

## 1. 五条线总览

| 线 | 主题 | 为什么值得做 | 主要风险 |
|---|---|---|---|
| A | 皮肤生态 | 数据驱动皮肤是上游最值钱的机制，做成生态才有用户自增长 | 需要网页工具与审核/兼容成本 |
| B | 行为与交互 | 猫「活着」的感觉来自行为，不是画功 | 手感调参耗时，容易做过头变吵 |
| C | 数据与可视化 | 把击键变成对用户有用的信息（KPM/热力图/周报） | 隐私边界必须守住 |
| D | 集成扩展 | 让猫出现在别的地方（直播/桌面/其它机器） | 依赖外部软件版本 |
| E | 工程与生态 | 让「别人能贡献」和「自己能升级」 | 需要 CI 与签名成本 |

## 2. 逐条创意（编号 + 技术路径 + 工作量）

工作量口径：**S** ≈ 1–2 天，**M** ≈ 3–5 天，**L** ≈ 1–2 周以上。

## 3. 优先级建议（先做什么）

| 顺序 | 组合 | 理由 |
|---|---|---|
| **P0（先做，性价比最高）** | C5 信息条可配置 · B1 打字节奏 · C1 KPM 角标 · B6 游戏静默 | 都是 S 量级，立刻提升「每天用」的体验 |
| **P1（做出差异化）** | A1 皮肤工坊 · A2 画廊 · C2 热力图 · D1 OBS 源 | 皮肤生态与可视化是护城河 |
| **P2（生态化）** | E1 自动更新 · E2 CI · A3 分享链接 · D4 跨平台 | 面向「给别人用」 |
| **暂缓** | E3 插件 · E4 格式 v2 · B4 多猫 | 复杂度高，等有用户再加 |

## 4. 明确不做（守住边界）

1. **不记录输入字符**：只保存物理键位/动作/统计，永不落字符与文本。
2. **不上传数据**：除「检查更新」外无任何网络请求；统计只在本机。
3. **不改上游仓库**：所有改动只在本仓；对外只提交 PR 或独立 fork。
4. **不做键盘记录器功能**：不提供键序回放、不做密码偷窥、不导出事件流。
