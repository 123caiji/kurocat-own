## 1. 生态规模与分层

| 层 | 代表 | 说明 |
|---|---|---|
| 运行时层 | `dsh-pet`（大肥鱼，0.4.9）、`dsh-pet-component`、`petdex`（Codex Pet 协议） | 提供透明窗 + 动画池 + 物理 + 协议；被 20+ 包复用/派生 |
| 形象层 | Live2D 系（`dsh-deepseek-live2d` 0.7.10、`dsh-live2d-pet`）、WebM 动画（`dsh-whale-pet` **95 个** 640×360 WebM）、像素（`dsh-famling`）、PNG 图集（`dsh-kujira-persona` 41 MB） | 形象成本差异极大：Live2D 要 48 MB 模型 + 100 MB Electron |
| 能力层 | 状态联动、工具调用、计费、记忆、任务 | 决定「实用性」，也是当前竞争主战场 |
| 社交层 | `dsh-zoo`（局域网串门/礼物/种菜/期货）、`dsh-pet-lan` | 玩法层，偏娱乐 |
| 市场层 | `dshmarket`、`dsh-market.com`、`@linxin666/dsh-client-ui-market` | 分发渠道 |

## 3. 赛道空白确认（我们的机会）

检索「keyboard / keystroke / 键盘 / 击键 / KPS」关键词命中的 DSH 包，**全部是快捷键/输入增强类**（`dsh-keyboard-shortcut`、`dsh-hotkey`、`@deepseek-ai/dsh-client-shortcuts`…），**没有一个做「按键可视化桌宠」**。

结论：**「能看到你按了什么键的桌宠」在 DSH 生态是空白**。我们的差异化成立，且与 `dsh-task-mascot` 的「工具级动作」不冲突（它讲 Agent 在做什么，我们讲你在做什么）。

## 4. 取舍矩阵

| 生态主流功能 | 我们做不做 | 理由 |
|---|---|---|
| 四态状态联动 | **做（P0）** | 最重要「实用」项，且我们是原生实现，成本极低 |
| 工具级动作 + 正在处理的文件/命令 | 做（P1，简化版） | 只需读会话状态文件，不需要 Electron |
| 任务清单/进度徽章 | 做（P1，简化） | 猫头顶一个小进度点即可 |
| 拖拽/甩动物理 | 部分（已有拖拽，甩动延后） | 原生做物理要重写手感，收益一般 |
| 摸头/点击回应 | **已有**，继续加强（好感度） | 我们已有摸头判定 |
| 喂食/饱食度 | 不做 | 与「工作陪伴」定位无关 |
| TTS 语音朗读 | 延后（P2） | 需要外部 TTS 依赖，破坏零依赖 |
| 点击音效 | 做（P1） | 可用 Win32 的 `PlaySound`/WaveOut，零依赖 |
| token 计费/余额 | 做（P2，只读角标） | 数据来自本地会话，不联网也能估 |
| 多宠/每会话一只 | 延后（P2） | 需要多实例协调，先做好一只 |
| 局域网社交 | **不做** | 与「离线零依赖」原则冲突 |
| 长期记忆/人格 | **不做** | 那是 LLM 侧的活，我们只做表现层 |
| Live2D | **不做** | 100 MB 运行时，违背产品定位 |
| 皮肤中心/市场 | 做（P1，静态画廊） | 我们的 `.kurocat` 数据皮肤天然适合做画廊 |
| 开机动画/壁纸引擎 | 延后（P2，可选） | 锦上添花 |
| 多语言 | 做（P1） | 已有 isEnglish 开关，扩成表 |
| **键盘可视化（我们的护城河）** | **持续加强（P0）** | 信息条 + 键帽气泡 + 组合键 + 鼠标三键 |

## 5. 技术约束（协作者约定）

见 [CONTRIBUTING.md](../CONTRIBUTING.md)。核心三条：

1. **只写 C++17**：不用 C++20/23 语法（concepts / ranges / coroutines / modules / `std::format` / `constinit` / `consteval` 等一律不用）。
2. **不新增第三方依赖**：保持「单文件 + 零运行时」，JSON 解析沿用 `shared/SkinSpec.hpp` 的手写解析。
3. **不引入新构建步骤**：`build-own.cmd` 一条命令必须能编出 exe。

## 7. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| DSH 生态变化快（248 包、日更） | 状态桥协议可能变 | 桥接层做成「读任意 JSON 字段、缺字段就回退」 |
| 生态主流是 Electron/Web | 我们受众小 | 主打「轻量 + 键盘可视化」，宁做窄而深 |
| 协作者可能引入新语法/新依赖 | 破坏零依赖与兼容 | CONTRIBUTING + CI 编译检查（C++17、无新增 deps） |
