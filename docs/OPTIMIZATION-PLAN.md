# 优化规划 · 生态调研 + 美观/实用改造（文档阶段）

> 2026-11-25。本文基于对 **DSH 插件生态的实际检索**（npm registry + 本机 DSH 插件目录）与 `docs/ROADMAP.md` 的既有方向，给出**可执行**的优化计划。
> 结论先行：**不要重做一只 dsh-pet**。我们的差异化在「键盘可视化 + 数据驱动皮肤 + 原生零依赖」，要做的是把这三件事做到最好，并补上 DSH 状态联动。

---

## 1. 生态调研结论（主流 DSH 桌宠插件）

### 1.1 玩家分布

| 项目 | 版本/更新 | 形态 | 核心能力 | 技术栈 | 许可 |
|---|---|---|---|---|---|
| **dsh-pet**（大肥鱼） | 0.4.9 / 11-14 | DSH 插件，Electron 独立透明窗 | 100+ 透明动画、可多开、拖拽甩动、余额/碎碎念、生态子包最多 | Electron + TS | 代码 MIT，素材禁商用 |
| **dsh-desktop-pet** | 0.2.0 / 09-11 | 纯插件（无独立进程） | **状态指示器**：空闲/思考/工作/等输入/完成/出错 | 插件内 React | - |
| **dsh-deepseek-live2d** | 0.7.10 / 11-06 | 插件 + Electron 透明窗 | Live2D 模型随状态换表情；模型 48MB + Electron 100MB 首次下载 | pixi.js + Live2D | 代码 MIT，Cubism Core 需自取 |
| **dsh-pet-component** | 0.2.5 / 10-18 | React 组件库 | 统一 dsh-pet / Codex Pet 两套协议，换 config 即换渲染 | React | - |
| **pet-link（壁纸引擎桥）** | 1.4.3 / 11-18 | dsh-pet 子包 | 壁纸吉祥物 ↔ 侧栏 联动演出 | - | - |
| **dsh-live2d-pet / dsh-pet-dafeiyu / dsh-xiaofu / deep-pet** | 0.1–0.3 | 插件/独立窗 | 各自角色与彩蛋（气泡、音效、余额查询等） | 混合 | 各异 |

### 1.2 分发渠道

- **dshmarket**（可视化插件市场，1.84.1）—— 站内逛、搜、一键装；
- **dsh-plugin-catalog**（**12,961 条**插件目录，JSON，npm 与 awesome-dsh-plugin.com 双源）；
- DSH 内置「自定义插件索引」（本机已启用）—— 可挂自己的索引。

### 1.3 它们的共性（我们要么对齐、要么刻意不跟）

| 共性 | 说明 | 我们的取舍 |
|---|---|---|
| 都是 **DSH 插件**（装完随 DSH 启动） | 用户零操作、能被市场发现 | **要跟进**：做一个薄插件壳把 exe 拉起来（见 P1） |
| 都与 **Agent 状态联动**（思考/工具/完成） | 桌面宠物真正的「用处」 | **要跟进**：这是最大缺口（见 P0） |
| 多为 **Electron/WebView 渲染** | 好看但吃内存（100 MB+ 运行时） | **不跟**：我们 1.3 MB 单文件、30 MB 常驻 |
| 形象多为**单一角色** | 动画多但换不了猫 | **不跟**：我们是数据驱动皮肤，7 款 + 可导入 |
| 极少做**键位可视化** | 只表达「状态」，不表达「你按了什么」 | **差异化死守**：这是我们的护城河 |

| # | 项 | 具体做法 | 量 | 验收标准 |
|---|---|---|---|---|
| U1 | **DSH 状态联动（G1）** | 猫读一个本地状态源（文件 `%APPDATA%\\KuroCatOwn\\dsh-state.json` 或 named pipe），映射到姿态：思考=歪头+「…」气泡；工具运行=敲键盘动画；等输入=招手；完成=竖尾+庆祝；出错=垂耳 | M | 状态切换延迟 < 150ms；DSH 不在时自动回落到普通模式 |

## 8. 不做 / 不做重复劳动

1. **不做第二个 dsh-pet**：不做多开、不做拖拽甩动物理、不做余额/碎碎念闲聊（那些是它的护城河）。
2. **不搬 Electron/Live2D**：我们的价值是「1.3 MB 零依赖」，换成 100 MB 运行时等于自杀。
3. **不做键盘记录器**：仍只存物理键位与聚合统计，不存字符、不联网。
4. **不改上游仓库**：所有改动留在本仓，皮肤格式继续兼容 v1。

## 9. 待你拍板的两个选择

1. **U1 状态联动的实现路径**：文件桥（最简单，`dsh-state.json`，任何进程都能写）还是 named pipe（更实时，但要写 DSH 插件侧代码）？建议**先文件桥**，D1 插件壳时再升级。
2. **P0 先做哪两项**：建议 **U1（状态联动）+ V1（信息条重设计）**——一个提实用性、一个提美观，正好覆盖你说的两个诉求。
