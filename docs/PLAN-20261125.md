# 规划 · 自有功能与视觉方向（2026-11-25）

> 前提：本项目**只引用上游的代码与皮肤**（chanke17/KuroCat, MIT），其余功能、视觉、交互按本项目自己的方向演进；上游作者在 README 致谢。
> 上一轮做的「顶部操作信息条」**已废弃**（评价：丑），源码已回滚，见 CHANGELOG。

---

## 1. 为什么信息条丑（复盘，避免再犯）

| 问题 | 具体 |
|---|---|
| 位置冲突 | 贴画布顶边，等于横在猫头上方，抢了猫的视觉主体 |
| 形态笨重 | 一整条深色胶囊 + 三种字号混排，像调试面板，不像陪伴物 |
| 信息冗余 | 键名 + 动作词 + 组合 + 三个字母灯 + 箭头，密度过高 |
| 与猫语义脱节 | 猫在敲键盘，信息却飘在远处，没有「从键盘长出来」的感觉 |

结论：**键位反馈应该长在键盘上（键帽气泡），而不是浮在猫头顶**。

## 2. 三个视觉方向（挑一个作为主线）

### 方向 A：极简 · 键帽气泡（推荐）

- 平时只有猫；**按键时才在键盘上方弹出圆角键帽**（1–6 个并发），带 1px 描边 + 软投影 + 按下 2px 位移。
- 组合键合并为一个宽键帽（`Ctrl+Shift+A` 显示成一颗长键帽）。
- 鼠标左/右/中键用不同描边色；滚轮用键帽侧一条竖线脉冲。
- 猫耳侧可选一枚 **KPM 小角标**（数字，默认关闭）。
- 优点：不抢主体、语义贴合「猫在敲键盘」、实现量小。

### 方向 B：底部键显窄条（可选开关）

- 屏幕底部一条高 26px 的窄条（左键名、中组合、右鼠标键），默认关闭；适合录屏 / 教学。
- 缺点：与猫分离，容易被当成「又一个键显工具」。

### 方向 C：状态徽章

- 猫旁一枚 24px 圆形徽章，只用颜色表达 DSH 状态（空闲 / 思考 / 工作 / 完成 / 出错），**不显示键名**。
- 优点：最不打扰；缺点：丢失「键盘可视化」这个护城河。

> 建议：**A 为主线**（键帽气泡是猫本体的一部分），B 作为可选开关，C 作为 DSH 联动的表达方式之一。

## 3. 功能路线（自有功能，全部可开关）

### P0 · 先做（4–6 天）

| # | 功能 | 说明 | 量 | 验收 |

## 4. 创新点（差异化，不与生态重复）

| 创新 | 为什么是差异 |
|---|---|
| **键盘可视化长在猫身上** | 生态里 248 个桌宠没有一个做「你按了什么」，都只做「Agent 在做什么」 |
| **节奏驱动** | KPM 越高尾巴 / 耳朵越快，慢下来打瞌睡——把「工作强度」变成可感知的动画 |
| **皮肤即数据** | `.kurocat` 是 JSON，可网页编辑、可分享、可版本管理；不是贴图 |
| **1.3 MB 原生** | 对比 Live2D 系 150 MB（模型 48 MB + Electron 100 MB）；低配机与老系统友好 |
| **完全离线** | 关掉上游更新后零出站请求；状态联动只读本地文件 |

## 5. 明确不做

1. 不做常驻信息条（已证明丑）。
2. 不做 Live2D / Electron（破坏体积与依赖优势）。
3. 不做喂食 / 社交 / 局域网（偏娱乐，非工作陪伴）。
4. 不做长期记忆 / 人格（属 LLM 侧）。
5. 不记录输入字符、不联网上传。

## 6. 验收线（沿用）

| 指标 | 红线 |
|---|---|
| 输入→画面延迟 | P95 ≤ 33 ms |
| 空闲 CPU | ≤ 1%（干净环境单实例；本机 GDI+ 基线偏高，按相对值评估） |
| 打字负载 CPU | 相对基线 +≤ 5% |
| 常驻内存 | ≤ 40 MB |
| 皮肤 / 主题切换 | < 200 ms，无闪烁 |
| 崩溃 | 2 h 无崩溃、内存增长 ≤ 10% |
