# P0-V1 · 操作信息条 + 关闭上游更新通道（已实现）

> 实施日期：2026-11-25。基线 commit `a8ee354`（回滚 tag：`pre-p0-20261125`）。

## 1. 改了什么

| # | 改动 | 文件 | 类型 |
|---|---|---|---|
| 1 | **新增操作信息条**：顶点居中圆角条；键名（主字，强调绿）/ 动作词 / 组合键（副字）；右侧 L·R·M 三键状态灯 + 滚轮方向箭头 | `windows/src/ActionHud.hpp`（新增 207 行） | 新增 |
| 2 | 键盘/鼠标/滚轮事件驱动信息条状态（只读既有事件，不新增采集） | `windows/src/main.cpp`（回调段 + 渲染段） | 修改 |
| 3 | `InputEngine` 增加 `onWheel` 回调（读既有 `RAWMOUSE.usButtonData`） | `windows/src/InputEngine.hpp` | 修改 |
| 4 | **安全：禁用上游自动更新通道**（原实现从作者私有域名下载 exe 并自动执行） | `windows/src/main.cpp`（`startAsyncUpdateCheck` 直接返回） | 修改 |

设计要点：

- **常驻不消失**：1.10s 后开始淡出，1.65s 后停在 55% 透明度；空闲显示「等待输入」（中性色），不会让人误以为没反应。
- **信息分层**：键名 15px 粗体 + 动作/组合 12px 常规，一眼能读到「刚才按了什么」。
- **性能**：字体、StringFormat、文本宽度全部静态缓存（每帧新建 `Font/FontFamily` 会吃满一个核——这是首版实测发现的问题，已修）。

## 2. 验证（本机实测）

| 项 | 方法 | 结果 |
|---|---|---|
| 编译 | `g++ -std=c++17 -O2`，无测试宏 | **0 error**，产物 1,309 KB |
| 渲染（按键态） | 测试构建强制「左Shift 按下」，截图统计顶部 36px | 强调绿 **184 px（1.42%）** → 信息条确实绘出 |
| 渲染（空闲态） | 无动作时截图 | 中性色 + 55% 透明（首版误用强调色，已修） |
| CPU 对比 | 同机 3 实例竞争下各测 10s | 基线 50.0% / 单核，含信息条 41.1% / 单核 → **差异在噪声内，无回退** |
| 内存 | 工作集 | 基线 49.3 MB → 新版 50.6 MB（+1.3 MB） |

> 说明：本机 GDI+ 软件绘制 60fps 的基线本身就有 ~30–50%（单核），绝对值不代表用户机器；关键在于**相对基线的增量 ≈ 0**。

## 3. 安全影响

| 面 | 结论 |
|---|---|
| 输入采集 | **零新增**。信息条只读既有 `InputEngine` 的键位枚举与鼠标按钮状态；新增的 `onWheel` 读的是既有 Raw Input 字段，没有新系统调用 |
| 隐私 | 仍只处理物理键位（`PhysicalKey` 枚举）与鼠标按钮，**不产生字符、不落盘、不联网** |
| 网络 | 本次**关闭**了唯一的出站入口（上游自动更新），自有分支现为**完全离线** |
| 代码执行入口 | 移除「下载 exe → 自动替换 → 启动」链路，消除不受控代码执行面 |
| 依赖 | 零新增（仅 GDI+ 与 Win32） |

## 4. 回滚方法（三步）

```bat
:: 1) 恢复到改动前的提交
git reset --hard pre-p0-20261125

:: 2) 或只回退单文件（本机已备份）
copy dist\backup\main.cpp.bak windows\src\main.cpp
copy dist\backup\InputEngine.hpp.bak windows\src\InputEngine.hpp

:: 3) 删掉新增头文件后重新编译
del windows\src\ActionHud.hpp
build-own.cmd
```

> 备份目录 `dist/backup/` 已加入 `.gitignore`，不入库；如需长期保留可自行拷贝。
